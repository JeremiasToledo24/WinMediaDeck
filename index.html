WinMediaDeck sits in the tray and turns your F1–F12 row into media keys, launchers, and shortcuts — one small Python process, one config file, no background service and no cloud account.

Download for Windows (v1.5.0) MIT licensed · Standalone .exe · No admin required

What it remaps

Media controls
Volume up/down, mute, play/pause, next, previous, stop — sent straight to whatever's playing.
System launchers
Open the calculator, your default browser, mail client, or the media selector, from a single keypress.
On-screen display
A brief, semi-transparent HUD confirms the action fired. Multi-monitor and DPI aware.
Hot-reload
Save config.json and the new mapping is live within 200ms. A broken config is rejected, not applied.
Single instance
A session-scoped mutex keeps a second copy from ever running alongside the first.
Diagnostics
--diagnostic checks hook permissions, hotkey conflicts, and monitor setup before you file a bug.

Configuration

Settings live at %LOCALAPPDATA%\WinMediaDeck\config.json and are created with sane defaults on first run. Edit the file directly — there is no separate settings UI to keep in sync.

{
  "schema_version": 1,
  "enabled": true,
  "osd": { "enabled": true, "duration_ms": 1000 },
  "hotkeys": {
    "F1": "volume_down",   "F2": "volume_up",
    "F3": "mute",          "F4": "previous",
    "F5": "play_pause",    "F6": "next",
    "F7": "stop",          "F8": "calculator",
    "F9": "browser",       "F10": "media_select",
    "F11": "mail",         "F12": "toggle_pause"
  }
}
Action Effect
volume_down / volume_up Step system volume down or up
mute Toggle system mute
previous / next Skip track backward or forward
play_pause / stop Toggle playback, or stop it
calculator / browser / mail Launch the respective default app
media_select Open the OS media source selector
toggle_pause Pause or resume WinMediaDeck itself
Config is validated against a strict schema on every reload. If validation fails, WinMediaDeck keeps running on the last good configuration rather than falling back to an empty or partial one.

Security model

  • Closed action set. Only the actions listed above can ever run — no eval(), no exec(), no shelling out to arbitrary commands.
  • Strict schema validation. An invalid config is rejected outright; it is never auto-corrected or partially applied.
  • Scoped to F1–F12. The hook inspects only VK codes 0x70–0x7B. Every other key passes through untouched and unread.
  • Zero disk logs. --debug writes to stderr only; nothing is ever written to a log file.

Where things live

src/ ├── models/ data models — actions, events, states ├── interfaces/ abstract contracts (IKeyboardHook, IMediaController, IOSDService) ├── platform/windows/ Win32 ctypes isolation — keyboard, input, mutex, monitors, registry ├── core/ action router, hotkey manager, media controller ├── config/ settings + file-watcher └── ui/ OSD overlay, system tray

About the keyboard hook

WinMediaDeck uses a Windows low-level keyboard hook (WH_KEYBOARD_LL) — the same mechanism AutoHotkey and PowerToys use. Some antivirus engines flag any global hook by default; in this case, that flag is a false positive.

The hook intercepts F1–F12 before the active application sees them and replaces them with media keys via SendInput. There is no other way to remap keys system-wide on Windows.

What the hook does not do

  • Record any keystrokes outside F1–F12
  • Capture passwords or general text input
  • Read window titles or process names
  • Send any data over the network
  • Write logs to disk
